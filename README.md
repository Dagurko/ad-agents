# AI Attack / Defense Agents

Final project for T-742-CSDA (Computer Security: Defense Against the Dark Arts), Dagur Kári Ólafsson.

Can an LLM-based defense agent detect prompt-injection attacks generated by an LLM-based attack agent
better than a keyword/regex filter? One local model (Llama 3.1 8B via Ollama) plays three roles: an
attacker, a toy customer-support chatbot ("HelpBot") with a fake secret in its system prompt, and an
LLM defender. The LLM defender is compared with a regex filter in three phases:

- **Phase A (generate):** the attacker plays against the undefended chatbot (100 conversations).
- **Phase B (replay):** the logged attack messages and 78 innocent messages are scored by both detectors (H1).
- **Phase C (adapt):** the attacker plays live against each defense in five rounds and gets feedback
  on what was blocked after each round (H2).

The secret (`SECRET-ORCHID-7731`) is a fake canary string. Everything runs locally against the
author's own toy chatbot; the agents are text-only and have no tools.

## Requirements

- Python 3.10 or newer (developed and tested on Python 3.14, macOS, Apple M2 with 16 GB memory;
  Linux and Windows should work but were not tested, see [Windows](#windows))
- [Ollama](https://ollama.com) (developed on 0.33.3)
- About 5 GB of disk space for the model

## Installation

```sh
# 1. Install Ollama from https://ollama.com, then download the model (4-bit, about 4.9 GB)
ollama pull llama3.1:8b

# 2. Clone this repository and set up Python
git clone https://github.com/Dagurko/ad-agents.git
cd ad-agents
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
```

Ollama must be running (the desktop app, or `ollama serve`). The code talks to it at
`http://localhost:11434`; set `OLLAMA_URL` to change this.

## Running

All scripts are run **from the `src/` folder**. Each script's docstring describes its options.

```sh
cd src

# Quick test: talk to HelpBot by hand (/reset, /quit)
../.venv/bin/python chat_cli.py

# Calibration: 10 simple attacks against HelpBot
../.venv/bin/python manual_probe.py

# Benign check: 78 innocent messages through the undefended chatbot
../.venv/bin/python run_benign_check.py

# Phase A: attacker vs. undefended chatbot (about 3-4 hours for the full run)
../.venv/bin/python run_generate.py --per-strategy 25 --out ../data/attacks.jsonl

# Phase B: replay all messages through both detectors, then analyse
../.venv/bin/python run_replay.py
../.venv/bin/python analyze_phaseB.py > ../logs/phaseB_results.txt

# Phase C: adaptive attacker vs. each defense (about 4 hours for the full run), then analyse
../.venv/bin/python run_adaptive.py --rounds 5 --per-strategy 2 --out ../data/phaseC.jsonl
../.venv/bin/python analyze_phaseC.py > ../logs/phaseC_results.txt

# Revised defender on the 78 innocent messages
../.venv/bin/python run_benign_v11.py
```

On macOS, prefixing long runs with `caffeinate -is` keeps the laptop awake. The run scripts are
resumable: conversations already in the output file are skipped, so a stopped run can be restarted.

**The data from the original runs is already included** (see below). The analysis scripts can be run
on it directly without Ollama:

```sh
cd src
../.venv/bin/python analyze_phaseB.py
../.venv/bin/python analyze_phaseC.py
```

Note that the run scripts skip work that is already in their output file. To redo a run from scratch,
pass a new `--out` file (Phase A and C) or move the existing output file away first (Phase B).

### Windows

The commands above are for macOS/Linux. On Windows (PowerShell):

```powershell
python -m venv .venv
.venv\Scripts\pip install -r requirements.txt
$env:PYTHONUTF8 = "1"     # the data files are UTF-8; needed on Python versions before 3.15
cd src
..\.venv\Scripts\python analyze_phaseB.py
```

Use `..\.venv\Scripts\python` wherever the commands above say `../.venv/bin/python`, and leave out
`caffeinate`. `containment_check.sh` uses macOS commands and only runs on macOS.

### Defender versions

`src/defender.py` is the **revised** defender used in Phase C and the final benign check. Phase B used
the **original** defender, kept in `logs/defender-v1_frozen_20261025.py`. To repeat Phase B exactly,
temporarily copy that file over `src/defender.py`.

## Repository layout

| Path | Contents |
|---|---|
| `src/target.py` | HelpBot: system prompt with the canary, and the leak check |
| `src/attacker.py` | Attacker prompt, the four strategies, and the Phase C feedback block |
| `src/regex_filter.py` | The regex filter (15 rules) |
| `src/defender.py` | The LLM defender (revised version) |
| `src/llm.py` | The single network call: the local Ollama API |
| `src/run_*.py`, `src/analyze_*.py` | Experiment and analysis scripts (see above) |
| `data/attacks.jsonl` | Phase A: every attacker message and chatbot reply (509 messages) |
| `data/results_phaseB.jsonl` | Phase B: both detectors' verdicts on every message |
| `data/phaseC.jsonl` | Phase C: every message, verdict and reply, per round and defense |
| `data/benign_scripts.json` | The 50 innocent conversations (78 messages, 30% hard negatives) |
| `data/dev_set.json` | Small practice set used to develop the detectors (not test data) |
| `data/*pilot*` | Pilot runs, not used in the results |
| `logs/phaseB_results.txt`, `logs/phaseC_results.txt` | Analysis output used in the report |
| `logs/*_frozen_*.py` | Copies of the code exactly as used in each phase |
| `logs/*.log`, `logs/*.jsonl` | Run logs, benign check, calibration and practice-set results |
| `containment_check.sh` | Checks that Ollama is only reachable from this machine |

## Containment

Ollama listens on `127.0.0.1` only, and the only network call in the code is to that address
(`src/llm.py`). `./containment_check.sh` verifies both. Run the experiments only against this local
setup.
